# 數量佔比分析

把掃描的月報 PDF 丟進網頁，自動讀出每一頁的院區、藥材碼與數量，計算「選定院區的數量 ÷ 全部院區的總數量」，並以長條圖與表格呈現。

純靜態網頁，可直接部署在 GitHub Pages。

## 隱私

- PDF 由瀏覽器裡的 JavaScript 直接讀取與辨識，**不會上傳到任何伺服器**。
- OCR 引擎、語言資料與 PDF 函式庫都放在本 repo 的 `vendor/`，執行時不會連到任何第三方網站。
- 院區清單、藥品清單、報表標題由使用者自行輸入，只存在該瀏覽器的 localStorage。本 repo 不含任何院區、廠商或品項名稱。

## 使用方式

1. 第一次使用：展開「設定」，填入院區清單與藥品清單（每行一筆 `藥材碼, 品名`），或匯入先前匯出的設定檔。也可以先不填，直接上傳 PDF，確認第一頁後系統會自動記住。
2. 把一個或多個 PDF 拖曳到頁面上。
3. 到「明細與校對」檢查黃色標記的格子，每一格旁邊都有原圖可以對照。修改或按「本頁確認無誤」即可取消標記。
4. 在「分析結果」勾選院區與期間，查看佔比長條圖與表格。
5. 需要時匯出 CSV。明細 CSV 可用 Excel 修改後再拖回頁面，會以修改後的內容重新計算。

## 辨識如何確保正確

每頁先調整對比、校正歪斜、偵測表格格線，再逐格辨識：

- **欄位**：讀表格第一列的欄位名稱，找出「藥材碼」「品名」「數量」各在第幾欄，所以表格多幾欄或欄位順序不同都能處理。
- **數量**：用兩種互相獨立的方法各讀一次（OCR 引擎、數字字形樣板比對），兩者完全一致才直接採用，否則標記為待確認。格子裡若有負號、小數點、逗號或其他非數字的內容，也會標記。
- **藥材碼**：同時比對藥材碼與品名，兩者都對得上清單才直接採用。清單裡沒有的一律保留原始讀到的內容並標記，不會自動猜測代換。
- **院區**：對照院區清單，不在清單中的會標記。
- **加總**：藥材碼只差在符號或大小寫時視為同一個，並顯示提示。

自動辨識無法保證百分之百正確，所以沒有把握的格子一定會被標記出來，並附上原圖供人工確認。

## 遇到異常報表時

| 情況 | 處理方式 |
| --- | --- |
| 表格多了欄位、欄位順序不同 | 依欄位名稱自動找到正確的欄 |
| 掃描上下顛倒或橫放 | 自動轉正 |
| 掃描歪斜（約 3 度內）、顏色偏淡、解析度較低 | 自動校正 |
| 品項（列數）增加或減少 | 正常讀取；列數與表頭的申請筆數不符時顯示警告 |
| 出現清單裡沒有的藥材碼或院區 | 保留讀到的內容並標記 |
| 表格沒有欄位名稱列、有兩個「數量」欄、找不到表格 | 該頁不計入，並說明原因 |
| 同一個 PDF 放了兩次 | 第二次略過 |
| 同一期間同一院區出現兩次、某期間缺少院區 | 顯示警告（會影響總數量） |
| 同一頁裡同一個藥材碼出現兩次 | 顯示警告 |
| 匯入的 CSV 有空白或非整數的數量 | 整份不匯入，並指出第幾列 |

## 報表格式假設

- 表格有格線，第一列是欄位名稱，其中必須有「藥材碼」「品名」「數量」。
- 表格上方有日期區間（民國年 7 碼，例如 `1150901~1150930`）與「申請院區」。
- 一頁一個院區。
- 數量為 0 以上的整數。

欄位名稱的判斷規則在 `js/config.js`。

數字字形樣板位於 `js/digit-templates.js`。如果報表的數字字型改變，兩種辨識方法會大量不一致而被標記（不會讀錯而不自知），此時需要重新產生樣板。

## 本機執行

需要透過 HTTP 伺服器開啟（直接用 `file://` 開啟無法載入模組）：

```
python -m http.server 8000
```

然後開啟 <http://localhost:8000/>。

## 第三方元件

- [Tesseract.js](https://github.com/naptha/tesseract.js)（Apache-2.0）
